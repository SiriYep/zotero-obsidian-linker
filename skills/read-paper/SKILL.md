# read-paper — 论文精读工作流

把一篇论文从「笔记里的 zotero 链接」一路读到「写回笔记的深度分析」。
核心理念：**骨架快速定位 + 对核心设计决策做"为什么"式深挖**——那种"为什么这么设计、为什么不那样做"的层层追问才是要追求的深度。目标深度的真实样例在 `references/example-analysis.md`，**首次精读写「图解」「深挖」前先读它校准**（quick 模式可跳过）。

> 两种模式：**① 首次精读** `/read-paper <论文名>`（下面 Step 1–8）｜**② 讨论固化** `/read-paper consolidate`（精读后把追问讨论提炼回笔记 → **读 `references/consolidate.md` 照做**）。
> 凡涉及**裁图 / 嵌图**（方法主图、用户点名某图）→ **读 `references/figure-extraction.md` 照做**。
> 本文件里 `references/…` 均指 `$SKILL_DIR/references/…`。

## 配置（装好后先把这节改成你自己的；正文只引用这些变量名）

- `$SKILL_DIR`（本 skill 目录）：`~/.claude/skills/read-paper`（默认安装位置，移动了就同步改这行）
- `$NOTES_DIR`（论文笔记目录）：`<填：你的 Obsidian 论文笔记文件夹的绝对路径>`
- `$VAULT_ROOT`（笔记所在 Obsidian vault 根目录）：`<填：vault 根目录的绝对路径>`
  ⚠️ 若机器上有多个 vault（嵌套 / 同名很常见），附件、`.obsidian` 配置一律认准这一个。
- **Zotero 附件库**：`~/Zotero/storage/<KEY>/*.pdf`（Zotero 默认数据目录；改过就改这行）
- **PDF key 字段**：`zotero_pdf_key`（回退 `zotero_item_key`）——由 zotero-obsidian-linker 写入笔记 frontmatter
- **笔记命名规则**：由 linker 的 filename template 决定，默认 `{{paperDate}}-{{shortTitle3}}-{{firstAuthor}}.md`（如 `260122-CosmosPolicyFineTuning-Kim.md`）
- **笔记语言**：中文，术语保留英文（见 Step 6；若你用别的语言记笔记，改 Step 6 的书写规矩和模板即可）
- **用户研究方向**（影响第八节「启发」的视角）：`<填：你的研究方向，如 机器人 / VLA>`
- **依赖工具**：poppler（`pdfinfo`/`pdftotext`/`pdftocairo`）、`python3` + Pillow；macOS 自带的 `mdls`/`sips` 可选、非必需

## 输入解析

用户调用时通常带一个参数（如 `/read-paper AC-DiT 重点看方法`），可能是：
- **固化讨论关键词**（`consolidate` / `sync` / `digest` / `wrapup`，大小写不限）→ 直接走**模式二**（读 `references/consolidate.md`），其后可选跟论文名。
- **论文名 / 关键词** → 去 `$NOTES_DIR` 匹配笔记
- **笔记文件名或路径**（.md）→ 直接用
- **PDF 路径**（.pdf）→ 跳过笔记定位，进入「无笔记模式」
- **focus 关键词**（"重点看实验""方法""quick / 快速过一下"）→ 调整产出侧重
- **什么都没给** → 看当前对话里最近提到的论文；仍不明确就直接问用户

## Step 1 · 定位笔记

1. 给的是 `.md` 路径 → 直接用。
2. 给的是论文名 / 关键词 → 在 `$NOTES_DIR` 里搜：
   ```bash
   ls "$NOTES_DIR" | grep -i "关键词"                 # 按文件名
   grep -ril "关键词" "$NOTES_DIR"/*.md               # 按 frontmatter 标题
   ```
   - **优先选 frontmatter 里含 `zotero_pdf_key` 的那个文件**（命名规则见配置节）。
   - 多个候选 → 列出来让用户选，**不要乱猜**。
3. 给的是 `.pdf` 路径 → 记为无笔记模式，跳到 Step 3。

## Step 2 · 从笔记解析 PDF

1. 用 Read 读笔记，取 frontmatter 的 `zotero_pdf_key`。
2. 解析 PDF 真实路径（文件名可能含空格）：
   ```bash
   ls -1 ~/Zotero/storage/<zotero_pdf_key>/*.pdf 2>/dev/null | head -1
   ```
3. 空 → 回退试 `zotero_item_key`；仍找不到 → 停下报错，提示用户检查 Zotero 是否已下载该附件。

## Step 3 · 确认 PDF 并估页数

```bash
ls -lh "<pdf 路径>"                                # 确认存在
pdfinfo "<pdf 路径>" | grep -i pages               # 精确页数（首选，poppler 自带、跨平台）
mdls -name kMDItemNumberOfPages "<pdf 路径>"       # 回退（仅 macOS，依赖 Spotlight 索引，刚下载的文件可能查不到）
```
路径含空格，命令里**务必加引号**。

## Step 4 · 分块读 PDF

用 **Read 工具的 `pages` 参数**，每次 ≤ 20 页：
- 短文（≤ 20 页）：一次读完。
- 长文（> 20 页）：① pages 1–20（abstract / intro / related / method 开头）→ ② 中段（method / experiments）→ ③ 末段（results / conclusion + 附录关键图表）。

**重要**：多页 PDF 必须带 `pages` 范围，否则会超时。读 PDF 用 Read（它能原生解析 PDF），不要用 pdftotext 当主力。

**可移植性回退**（在没有原生 PDF 分页读取工具的 agent 上，如 Codex）：
```bash
pdftotext -f <起页> -l <止页> "<pdf 路径>" -        # 分块提取文本
pdftocairo -png -r 150 -f <页> -l <页> "<pdf 路径>" /tmp/pg   # 关键图表页渲成 PNG 再看图
```

## Step 5 · 读笔记现状（保护手写内容）

写之前先看 `## Notes` 区，按情况处理：
- **空 / 只有占位** → 待会儿直接填进去。
- **已有手写内容** → **绝不覆盖**，把分析作为独立区块追加到文件末尾。
- **已存在上次本 skill 生成的区块**（被 `<!-- ai-read-paper:start -->` / `<!-- ai-read-paper:end -->` 包裹）→ **只替换这对标记之间的内容**（重跑即更新，不堆叠重复）。标记之外的一切都不动。

取当天日期：`date +%Y-%m-%d`

## Step 6 · 按「骨架 + 深挖」写分析

用下面的模板，按配置节指定的笔记语言书写。骨架部分（一~五）求准求精，别复述废话；
**第六部分「深挖」是灵魂**——要钻到设计动机与取舍，像拆解一样讲清"为什么这么设计、为什么不那样"。
**动笔前读 `references/example-analysis.md`**：样例 1 是「图解」的目标深度，样例 2/3 是「深挖」的目标深度（quick 模式可跳过不读）。

**术语保留英文，不硬翻**：方法 / 架构 / 损失函数 / 算法等的**专名**——如 Flow Matching、Conditional Flow Matching Loss、Transformer、Mixture-of-Transformers 等——一律用英文原文，别生造译名（写「Conditional Flow Matching Loss」，**不要**写「条件流匹配损失」）。模型 / 系统 / 数据集名（π0、VGGT、PaliGemma、Ego4D…）同理保留原文。仅当某概念已有约定俗成的通行译法时（如「注意力机制」「卷积」）才用译文。拿不准就保留英文原词。

**数学公式用 `$` 包裹（仅笔记正文内，Obsidian MathJax 渲染；对话/摘要输出里别加 `$`，改用 Unicode）**：凡数学符号 / 变量 / 下标 / 复杂度式，别让它们以裸文本（`m_{t+1}`）或反引号代码（`` `π_HL` ``）的形式散在正文里——那样不会被渲染成公式。
- **行内公式**用单 `$…$`，例如 `$m_{t+1}$`、`$K \ll T$`、`$\pi_{\mathrm{HL}}$`、`$O(Kn^2+nK^2)$`。
- **独立成行的公式**单起一行用 `$$…$$`。
- 多字符下标用花括号（`\pi_{\mathrm{HL}}` 而非 `\pi_HL`），希腊字母 / 关系符尽量用 LaTeX 宏（`\pi`、`\approx`、`\ll`、`\mid`、`\cdot`、`\times`）以保证渲染干净；实在拿不准时，至少保证用 `$…$` / `$$…$$` 把公式包住。

**正文 `[[ ]]` 只链真实存在的 vault 论文笔记**：写回的是用户的 Obsidian vault，`[[名]]` 会解析成 vault 里的笔记。只在**确有对应论文笔记**时才用；**拿不准目标是否存在就写纯文本**（方法名 / 模型名照「术语保留英文」处理）。**绝不**把 vault 之外命名空间的标识（如 AI 助手自身记忆 / 会话系统里的文件名）塞进 vault 正文的 `[[ ]]`——那是另一套命名空间、会变成无意义死链。（图片嵌入 `![[IMG-…]]` 不受此限。）

**「四、方法」先图后文**：先**自行判断**全文哪张图最能表达**方法 / 架构 / pipeline**——**不一定是 Fig 2**！可能是 Fig 1 / Fig 3 / 任意编号（通常是 intro 后第一张系统总览图，或 method 节里的架构图；判据：这张图是不是在讲「方法怎么 work」，而非结果图 / 数据图 / 任务示意图）。选定后按 `references/figure-extraction.md` 提取，放「四、方法」**最开头**，紧跟一段**详细图解**；**之后**是「**系统性总结**」（整体框架 / 关键技术点 / 与先前方法的本质区别）——它与图解里的「整张图想说的事」**同级**，必须用粗体小标题 `**系统性总结**` **单独起头**，别让那几条挂在「整张图想说的事」列表底下、看起来像图解的下属。**若全文没有合适的方法图**（纯理论、或图全是结果 / 实验图），就**省略「图 + 图解」整块**，直接写系统性总结。quick 模式可只放图、省图解。

> **图解要写到什么程度（关键）**：这不是翻译 caption，而是**像给人逐帧拆解一样把整张图讲透**，要**充分、分条**。具体：
> 1. 先一句 `>` 引用做**总述**（整体怎么划分：左右两半 / 自上而下 pipeline / 各级模块），`>` 只用在这句、别整段塞进引用。
> 2. 再按图里的**区块**（如 high-level / low-level、encoder / backbone / head、pipeline 各级…）**逐块**拆，每块用带粗体小标题的要点列表讲清：核心**方块/模块**是什么（连同图上印的标注文字）、**逐个输入**箭头喂的是什么（对应论文里的符号 / 含义）、**逐个输出**是什么、这块的***关键点*（设计取舍）**。
> 3. 末尾「**整张图想说的事**」做综合（共享了什么、本质区别、谁是关键接口），并**顺着图里的具体例子把数据流从头到尾走一遍**。
> 4. 篇幅长没关系，宁详勿略；术语 / 符号照「术语保留英文」「公式用 `$`」两条规矩。目标深度 = `references/example-analysis.md` 样例 1。

填好后整块就是要写进笔记的内容（把 `{{DATE}}` 换成真实日期，占位 `…` 换成实际内容）。
**若配置节的笔记语言不是中文**：把模板里的骨架标题（"一、速览"…）、固定小标题（"图解""整张图想说的事""系统性总结"…）和正文一并用该语言书写，模板**结构**与 `<!-- ai-read-paper -->` 标记原样保留：

```markdown
<!-- ai-read-paper:start -->
### 🤖 AI 精读分析 · {{DATE}}

#### 一、速览
- **标题 / 作者 / 机构**：…
- **发表**：年份 · 会议或期刊 / arXiv
- **TL;DR**：1–2 句说清这篇干了什么。

#### 二、研究问题
要解决什么 + 为什么重要（1–3 句，点到本质难点，别停留在表面）。

#### 三、核心贡献
intro 末尾那几条，凝练成 2–4 点。

#### 四、方法

![[IMG-<笔记名>-<时间戳>.png]]

**图解 · 图 X（<点题：这是什么图>）**
> 一句话总述：整体怎么划分（左右两半 / 自上而下 pipeline / …）、在讲什么。（`>` 只用在这句，别整段塞进引用）

**<区块 A（它负责什么）>**
- <核心方块 / 模块>：<图上标注文字> —— <含义>
- **输入**：逐个数据流框 / 箭头 → 对应符号 / 含义
- **输出**：逐个输出 → 对应符号 / 含义
- *关键点*：这块最该注意的设计取舍

**<区块 B（…）>**
- …逐框逐箭头同上

**整张图想说的事**
- 综合：共享了什么 / 本质区别在哪 / 谁是关键接口
- 顺着图里的具体例子，把数据流从头到尾走一遍

**系统性总结**
- **整体框架 / 架构**（可含图里没画的：训练数据、规模、与先前方法的本质区别等）
- 关键技术点
- 与先前方法的**本质**区别

#### 五、实验
- 数据集 / 任务、对比基线、评测指标
- 关键定量结果（带数字）
- 消融揭示了什么

#### 六、核心机制深挖
挑这篇 2–4 个最关键的设计决策，每个做"为什么"式追问：
- **为什么需要它？** —— 不这么做会怎样（动机）
- **为什么是这个方案，而不是显而易见的替代？** —— vs. baseline / 朴素做法 / 其他架构（取舍）
- **代价是什么？** —— 它引入了什么新假设或新限制

> 这部分别泛泛复述，要把设计背后的逻辑拆开讲透——目标深度 = `references/example-analysis.md` 样例 2/3。

#### 七、批判性评价
- 创新性（1–5 分）+ 一句理由
- 实验是否充分可信？有无明显缺口或不公平对比？
- 写作清晰度
- **结论：值得精读 / 略读 / 跳过？**

#### 八、局限与启发
- 论文自认 + 你观察到的局限
- 对用户研究方向（见配置节）的潜在启发或可借鉴点
<!-- ai-read-paper:end -->
```

## Step 7 · 写回笔记

- **无笔记模式** → 不写文件，直接在对话输出完整分析。
- **空 Notes** → 用 Edit 把整块插到 `## Notes` 行的正下方。
- **已有手写内容** → 用 Edit 在文件**末尾**追加（前面空一行 + `---` 分隔），整块用 start/end 标记包裹。
- **已存在旧 AI 区块** → 用 Edit 替换 start/end 之间的内容；**替换前先扫旧块里的 `![[...]]` / `![](...)` 插图、记下各自所在小节，regenerate 后原样补回**（否则会把之前裁好的图冲掉——见 `references/figure-extraction.md` 护栏 C）。

写完务必确认：frontmatter、`# 标题`、zotero linker 注释块（`<!-- zotero-obsidian-linker -->`）、以及用户原有的 Notes 内容都**原封不动**。
能用 Edit 精确插入就别用 Write 整体覆盖。

**写回后自检（防乱码 token，模式一 / 模式二写回后都做）**：偶尔模型会串入异常字符（比如把"四"写成西里尔文 четыре）。写完跑下面命令扫这篇笔记，命中就地改回正确文字。正则按「中文 + 英文笔记」设定——西里尔 / 韩文 / 日文假名 / 希伯来 / 阿拉伯文几乎不可能是正文，希腊字母 σ / λ / μ 是合法数学符号、已排除；**若你的笔记本身含这些文字（如日文笔记），请相应缩小正则范围**。

```bash
perl -CSD -ne 'print "L$.: $_" if /[\x{0400}-\x{04FF}\x{AC00}-\x{D7A3}\x{0590}-\x{05FF}\x{0600}-\x{06FF}\x{3040}-\x{30FF}]/; close ARGV if eof' "<笔记路径>"
```

无输出 = 干净。

## Step 8 · 对话摘要

写回后，在对话给一份简短摘要（3–5 句）：
- 这篇在做什么 + 最值得记的 1–2 个点
- 值得精读 / 略读 / 跳过
- 告诉用户：写回了哪个文件、用的哪个 PDF

## focus 调整

- "快速 / quick / 过一下" → 只写骨架（一~五）+ 极简深挖，跳过细节。
- "实验 / experiments" → 扩展第五部分。
- "方法 / methodology" → 扩展第四 + 第六部分。
- 默认（无 focus） → 全写全，深挖给足。
