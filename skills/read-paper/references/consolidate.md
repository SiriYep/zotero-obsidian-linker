# 模式二 · 讨论固化（探讨模式）

适用：第一次精读笔记已生成后，用户在对话里继续追问细节、来回探讨，直到觉得真正读懂；然后由用户触发，把这段讨论里有价值的内容**提炼**、写回**同一篇**笔记。

## 触发（任一即可）

- **命令式（推荐）**：`/read-paper consolidate [论文名]`——也认 `sync` / `digest` / `wrapup` 等同义词，大小写不限。
- **自然语言**：用户说「固化讨论」「把讨论更新进笔记」「consolidate」之类。
- **兜底**：重新 `/read-paper` 且该笔记已有 `ai-read-paper` 区块、本轮又有过实质讨论时——先**确认一句**是要固化讨论还是重读，再执行（避免误判）。

## 怎么做

1. **定位笔记**：就是这轮在读 / 讨论的那篇（通常已知；不确定就按模式一 Step 1 定位）。
2. **回看对话**：从第一次生成笔记之后到现在，扫一遍讨论。**提炼，不是流水账**——只挑有价值的：
   - 用户追问的关键问题 + 讨论得出的结论
   - 讨论中才想明白、第一次没写到的更深理解
   - 对第一次分析的纠错 / 修正
   - 用户自己的观点、与其研究方向的联系
   - 跳过：寒暄、走偏的支线、第一次分析里已写过的。
3. **写回**（独立讨论区，**绝不改动**第一次的 `ai-read-paper` 区块）：
   - 用一对 `<!-- ai-discussion:start -->` / `<!-- ai-discussion:end -->` 作为整个"讨论区"的**外壳**，放在 `ai-read-paper` 区块**之后**。
   - 外壳内部，**每一轮讨论 = 一个带日期的独立小节** `### 💬 讨论提炼 · <date>`。
   - 取日期：`date +%Y-%m-%d`。
4. **多轮（重要）**：以后再翻出这篇继续聊、再固化时，**不要和旧的合并**——在外壳内、已有小节的**后面**追加一个新日期的 `### 💬 讨论提炼 · <新date>` 小节，按时间从上往下排。（同一天多次可在日期后加 `(2)`、`(3)` 区分。）
5. **纠错原则**：默认**不改写**第一次分析（保留"初读"原貌）。若讨论纠正了其中某处，在「更深的理解 / 修正」里点名："第一次第 X 节的说法应更正为……"。
6. **书写规矩与自检同模式一**：术语保留英文、公式用 `$`、`[[ ]]` 只链真实存在的笔记（SKILL.md Step 6）；写回后跑 SKILL.md Step 7 的**乱码自检**。

## 模板（写进 `ai-read-paper` 区块之后）

```markdown
<!-- ai-discussion:start -->

### 💬 讨论提炼 · {{DATE}}

**Q：<用户追问的关键问题>**

A：<讨论得出的精炼结论>

**Q：<下一个问题>**

A：<结论>

#### 更深的理解 / 修正
- <讨论中才浮现的、第一次没写到的更深理解>
- <若纠正了第一次分析：点名第几节、原说法 → 更正为……>
- <用户自己的观点 / 与其研究方向的联系>

<!-- 下次再讨论：在此 end 之前另起一个「### 💬 讨论提炼 · 新日期」小节，勿合并旧的 -->
<!-- ai-discussion:end -->
```
