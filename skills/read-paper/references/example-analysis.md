## 样例 1 · 图解的目标深度（MEM 论文 Figure 2，架构总览图怎么拆）

要点：总述只占一句 `>` 引用；然后**逐区块**拆，每块写清模块名（连同图上印的标注文字）、**逐个输入箭头**、**逐个输出**、一条*关键点*；末尾「整张图想说的事」做综合，并**顺着图里的具体例子把数据流从头到尾走一遍**。

> 一条竖虚线把系统切成左右两半：左 = high-level policy（管长时**语言**记忆），右 = low-level policy（管短时**视频**记忆）；本质上是把分解式画出来，并用「做土豆泥菜谱」的具体例子把数据流串起来。

**左半 · high-level policy（长时语言记忆）**
- 中间大方块 **π0.6-mem high-level**，副标 *pre-trained VLM: SigLIP (400M) + Gemma (4B)*（一排排小圆角块 = transformer）。
- **三路输入（底部）**：
    - 粉红框 "Prepare the recipe." —— 任务目标 $g$。
    - 粉红框（标 "$m_t$ : language memory"）："I prepared the pot and got the potatoes, milk, and butter. I moved to the drawer." —— 上一步的语言记忆 $m_t$，记着「已经干了啥」。
    - 三张厨房相机画面 —— 当前观测 $o_t$。
- **两路输出（顶部）**：
    - 粉红框 "$m_{t+1}$ : updated language memory"："…I opened the drawer with the masher." —— 更新后的记忆，新追加的后半句就是这一步的语义事件。
    - 框 "language subtask"："Pick up the masher" —— 下一个子任务指令 $l_{t+1}$。
- *关键点*：high-level 拿**自己上一步吐出的** $m_t$ 预测 $m_{t+1}$——这条自更新语言链正是它与以往 high/low 拆分的本质差别。

**右半 · low-level policy（短时视频记忆 + 出动作）**
- （…同样逐框、逐输入箭头、逐输出地拆，此处略）

**整张图想说的事**
- **共享 backbone**：两半都是 SigLIP + Gemma，只是扮两个角色；low-level 多挂 action expert + noise 才产连续动作。
- **两种记忆 / 两种模态**：左 = 语言（语义、可压缩、自更新，宜长时）；右 = 视频（稠密帧、沿 time 轴、video encoder 压缩，宜短时解遮挡 / 估动态）。
- **$l_{t+1}$ 是咽喉**：high-level 用它把「该做哪个子任务」交给 low-level——长时规划与短时执行就此解耦。
- **顺着例子走一遍**：已备锅、取土豆牛奶黄油、走到抽屉前（$m_t$）→ 这一步打开抽屉，high-level 把记忆补成「打开了放 masher 的抽屉」并发「Pick up the masher」→ low-level 据此 + 最近几帧 → 输出真正去抓 masher 的动作。

## 样例 2 · 深挖的目标深度（MEM「为什么 language memory 要压缩」）

要点：每个设计决策问满三层——**为什么需要 / 为什么不是显而易见的替代 / 代价是什么**；敢于点出全文最妙的一笔并单独标记；结论落在「可迁移的设计原则」而不是复述。

**② 为什么 language memory 要「压缩、丢信息」，而不是老老实实拼接历史？——全文最精彩的一笔**
- **为什么需要**：naive 拼接会撞上训练-推理分布偏移——训练 demo 近最优、每个子任务只说一次；推理时反复失败会反复复述同一子任务（pick up bowl ×3 → place），序列 OOD 拖垮策略。压缩把「失败重试」这类推理期才出现的冗余抹掉，让推理序列回到训练分布；顺带让摘要简短 → 推理快。
- **真正的洞见（值得单独记）**：长时与短时对「失败信息」的取舍**恰好相反**——长时记忆**主动丢弃**失败尝试（只保留语义进展，降分布偏移）；短时记忆却**刻意保留**失败尝试（in-context adaptation 正是靠「短时记忆里看到自己上一抓失败了」才学会换策略）。同一套系统里，两个模态采用**互斥的信息保留哲学**，且各自的理由都成立。
- **代价**：何时压、压什么是要**学**出来的，依赖 LLM 生成标签的质量；丢信息天然有「丢掉日后才需要的东西」的风险，论文用「最小相关集足矣」搪塞，但缺乏对压缩失误的鲁棒性分析。

## 样例 3 · 追问的风格基线（手写 AC-DiT 笔记的「为什么不那样做」连环反问）

要点：这是手写笔记的风格源头——对**每个看似显然的替代方案**单独立题反驳，直到设计的必然性浮出来。深挖部分要带着这种劲头写。

**为什么不能仅靠干净数据让 DiT 自己学会阶段？**
即使动作数据理想干净（移动阶段仅 2 维非零、操纵阶段仅 14 维非零），DiT 依然学不出稳定阶段：① 视觉分布高度重叠——30cm vs 50cm 的视觉差异极小但动作阶段完全不同 → 标签冲突；② diffusion 不做阶段分类——它对全部 16 维同时 denoise，不会"先判断阶段再决定哪些维度该为 0"；③ 阶段是 latent variable 不是视觉函数——需要"任务进度"才能判断，单帧视觉给不了。

**为什么不直接把 base action/pose concat 进 DiT？**
推理时 ground-truth 不可得、只能依赖自身预测 → error accumulation 越走越偏；而 mobility latent 是抽象阶段表示，对噪声不敏感、不随单步动作误差累积失控。

**为什么不用 Mamba/SSM 做阶段建模？**
阶段判断不是"长程时序记忆"问题——它主要依赖当前几帧的几何关系；SSM 会"记太多"反而让学习目标不清晰。阶段建模 ≠ 时序建模。

**为什么不加一个手工 phase label（0/1）？**
人工阈值本身不稳；离散 label 表达不了中间态、不利于平滑切换；连续 latent 反而能自发学出"进度"。
